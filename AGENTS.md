# Софія збирає своїх

- Общение по-русски, весь интерфейс по-украински.
- Арт-дирекция в design.md. Данные события в src/config.ts.
- Нативный скролл; GSAP с useGSAP и cleanup. Учитывать prefers-reduced-motion.
- RSVP только в localStorage: нельзя сообщать, что София получила ответ.
- Сохранять пустую локацию и не показывать маршрут без конфигурации.
- Проверки проекта: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`. Для визуальной проверки использовать 320, 375, 390, 430, 768, 1024 и 1440 px; артефакты — в игнорируемой `output/`.
- Не добавлять по умолчанию eyebrow, overline, секционные индексы и декоративные номера глав. Иерархию строить масштабом, композицией и пространством; даты и функциональные подписи сохранять.

## GitHub: постоянное разрешение для dr2

- Репозиторий этого проекта: `https://github.com/elizabeth445/dr2.git`, ветка `main`, remote `origin`. Область разрешения ограничена `elizabeth445/dr2`; общие запреты на публикацию в других репозиториях сохраняются.
- Пользователь заранее разрешил после каждой успешно завершённой задачи на изменение сайта автоматически выполнять полный цикл: локальные правки → проверки и сборка → понятный коммит → push в `main` → проверка отправленного SHA на GitHub. Для обычного коммита и push в этот репозиторий повторное подтверждение не требуется. Это проектное разрешение уточняет общий workflow из `~/.codex/AGENTS.md`.
- Перед коммитом и push проверять `git status`, diff, staged diff, remote и ветку; очищать только подтверждённо ненужное, исключать секреты и генерируемые артефакты. Коммитить только предназначенные для задачи изменения. Не создавать пустые коммиты.
- Использовать локальный Git или подключённый GitHub-плагин. При работе через плагин сохранять родителя текущей ветки, сверять её SHA перед обновлением и затем синхронизировать локальную историю. Не считать отправку успешной без проверки удалённого коммита.
- При проваленных проверках, конфликте, изменении удалённой ветки во время работы или ошибке Git остановить публикацию и сообщить о проблеме. Не использовать force push, не удалять историю и не перезаписывать чужие изменения.
- После задачи кратко сообщать по-русски, что изменено, результаты проверок, статус push и SHA коммита.
- Это разрешение относится к публикации кода в GitHub. Самостоятельный deploy сайта на Vercel или другую платформу не разрешён.
- Vercel: статический Vite-проект, команда `npm run build`, output `dist`. Клиентскому сайту не нужны серверные секреты; не добавлять инфраструктуру без задачи.
- `public/images/cake.jpg` и `public/images/cheers.jpg` используются. Промпты и арт-дирекция — в `design.md`; `package-lock.json`, исходники, настройки и документацию сохранять.
